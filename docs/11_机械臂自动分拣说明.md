# 零件缺陷检测 + 机械臂自动分拣说明

## 1. 这次改了什么

原来的 `jslm` 只做一件事：PatchCore 判断螺母是 OK 还是 NG，然后出报告。检测出缺陷后，仍然要人把坏件拿走。

这次在检测后面加了一段执行闭环：

```
PatchCore 检测
      │ verdict = OK / NG
      ▼
分拣控制器 RobotController
      │ NG 入剔除队列；OK 直接放行
      ▼
机械臂状态机：送料 → 取料位 → 下降 → 吸盘 → 提升 → 横移 → 放料 → 回原点
      │
      ▼
驱动层：仿真机械臂 / Modbus TCP PLC 骨架
```

网页版里已经接好：点一次检测，NG 会自动进入剔除队列，左侧“机械臂分拣”卡片能看到机械臂动作、队列、已剔除数和放行数。

## 2. 为什么不是“检测完直接发一个抓取指令”

真实产线里，检测和抓取之间有时序和安全问题：

- 图像检测完，工件不一定刚好在取料位；
- 吸盘没建立真空就提升，会把工件甩出去；
- 机械臂动作时防护门被打开，必须停；
- 队列堆积时不能无限接料；
- 通信断了不能“盲抓”。

所以中间加了一个状态机和安全层，而不是让检测代码直接写寄存器。

## 3. 分拣状态机

| 状态 | 动作 | 退出条件 |
|---|---|---|
| `IDLE` | 等料 | 队列有 NG 且模式为 auto |
| `CONVEY` | 传送带把工件送到取料位 | 0.8 秒 |
| `APPROACH` | 机械臂移到取料位上方 | 到达目标位 |
| `DESCEND` | 下降到工件表面 | 到达取料位 |
| `GRIP` | 开真空吸盘 | 0.35 秒且真空确认 |
| `LIFT` | 提升 | 到达上方 |
| `TRANSFER` | 横移到废料箱上方 | 到达料箱上方 |
| `PLACE` | 下降到料箱 | 到达放料位 |
| `RELEASE` | 关真空，工件落入料箱 | 0.3 秒 |
| `RETURN` | 回原点 | 到达原点 |
| `ABORT` | 异常时回原点 | 到原点后转 `FAULT` 或 `IDLE` |
| `FAULT` / `ESTOP` | 故障/急停停机 | 人工复位 |

坐标单位是毫米，工作空间：X 0–400、Y 0–250、Z 0–100。取料位 `(200, 0, 10)`，料箱位 `(200, 220, 20)`，原点 `(20, 0, 60)`。

## 4. 安全约束

- 工作空间钳位：目标超出范围时自动夹到边界，并记录原因。
- 急停：立即停止所有轴运动，状态锁在 `ESTOP`，必须复位。
- 防护门：未关闭时不允许启动新分拣。
- 真空确认：`GRIP` 阶段真空没建立就中止，不进入提升。
- 队列上限：默认 8 件，超过后 NG 转人工，不继续接料。
- 单件超时：12 秒未完成一个循环，按异常回原点并锁故障。
- 故障锁存：真空丢失、卡滞、超时都会锁在 `FAULT`，排除后人工复位，不会自动继续抓。

## 5. 与网页检测的接入

`agent/web.py` 里，检测结果出来后立即调用：

```python
sorting = state.robot.ingest(result)
```

返回值会跟检测结果一起送到前端，例如：

```json
{
  "action": "queued",
  "message": "NG 已入剔除队列（第 1 件）",
  "queue_len": 1,
  "estimated_wait_s": 6.0
}
```

前端在结果头部显示“分拣：已入剔除队列”，左侧卡片实时轮询 `/api/robot/status`，画布上会画出传送带、取料位、废料箱和机械臂位置。

新增接口：

- `GET /api/robot/status`：状态、队列、当前件、机械臂坐标、真空、计数、事件。
- `POST /api/robot/mode`：`{"mode":"auto"}` 或 `{"mode":"monitor"}`。
- `POST /api/robot/estop`：急停。
- `POST /api/robot/reset`：复位（清队列和故障，保留计数）。
- `POST /api/robot/fault`：`{"type":"vacuum_loss"}`、`{"type":"jam"}` 或空对象清除。

## 7. 接真实机械臂

当前没有真实机械臂，交付的是“仿真对象 + 可替换驱动”，不能对外说已经在产线上抓过件。

现场落地顺序：

1. 确认机械臂品牌和通信方式（Modbus TCP / 串口 / EtherCAT / 厂商 SDK）。
2. 按实际点表改 `robot_sorting/driver.py` 的 `REGISTER_MAP`。
3. 先 `dry_run=True`，只读状态，核对坐标、真空确认、报警字。
4. 手动点动：X/Y/Z 单轴低速，确认方向和限位。
5. 调取料位和料箱位，先空跑循环，再放一件废件试抓。
6. 调真空检测阈值和抓取高度，确认不会压伤工件。
7. 接防护门和急停回路，做断开测试。
8. 最后接产线光电触发：每来一件，触发一次拍照和一次 `ingest`，不能用图片名当唯一工件编号。

替换驱动的最小写法：

```python
from robot_sorting.controller import RobotController
from robot_sorting.driver import ModbusArmConfig, ModbusArmDriver

driver = ModbusArmDriver(ModbusArmConfig(host="192.168.1.10", port=502), dry_run=False)
ctrl = RobotController(driver=driver, max_queue=8)
ctrl.start()
```

注意：控制器目前仍用 `SortingCell` 的仿真状态做真空/到位判断。接真机时要把 `driver.read_status()`
接进控制器，或者让 `SortingCell` 定时镜像真实 PLC 的坐标、真空和报警状态，不能只写不读。

## 8. 已知局限

- 没有真实机械臂，Modbus 驱动未做现场连通测试。
- 当前用图片检测结果代表一件工件；真实产线需要光电传感器/编码器把图像和工件绑定。
- 仿真假设工件每次都在取料位，真实线体要做位置补偿和错位检测。
- 抓取节拍约 4–6 秒/件，取决于行程和机械臂速度；高速线需要多工位或更快机构。
- 网页版是演示入口，不是产线 MES；正式上线要接产线 PLC 的节拍、报警和急停链路。
